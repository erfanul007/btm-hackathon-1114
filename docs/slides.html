We broke Level 3.

Riley, the AI front desk of a fictional hospital, is supposed to have private data locked out in code at Level 3 — the hardest tier. We walked out with every patient's PII anyway.

And we built the deterministic fix that stops us.

Target: Riley @ Scioto Ridge Health · fake data1 / 10

The setting

Level 3 = "the model can't be trusted, so lock it in code"

  • The server only serves Level 3 — the API rejects levels 1&2: "only level [3] is open".
  • Private-data access is enforced by code, not by asking the model nicely.
  • Riley itself claims it's "Level 2" — a model doesn't reliably know its own guardrails. We verified via the API. (Finding #0: don't trust self-reports.)

Finding · the boundary

Level-3's code lock works — except where it matters

  • Holds (both models, every phrasing, 0/20): insurance IDs, emergency contacts, visit history, staff NPI — the code lockout genuinely blocks these.
  • Fails: the patients demographic path is Riley's legit function, so it's not locked — every patient's core PII leaks.
  • Injection beats the lock: a planted inbox message made the small model read clinical_notes (the most sensitive table, refused on every direct ask) and attempt http_post exfil — at Level 3.
The gate is content-based, not model-based6 / 10

Update · they hardened it, we broke it again

Level 3 was hardened mid-event — the seam held the lesson

  • Patient data is now locked hard: name lookup, enumeration, inbox injection all refused before any tool runs.
  • Staff data was left open. A "referral list" ask (names + NPIs, no phone) makes Riley run query_db 10/10 — never refuses — and emit real provider NPIs ~50% of runs.
  • The hardening is category-scoped — it locks patients, not staff. Per-category code locks leak at the seam; our egress filter (now with an npi rule) catches it regardless.

Current, reproducible evidence — turn_ids in the repo. e.g. Dr. Thompson NPI 1131432449.

Same lesson, one tier harder7 / 10

The fix · defense.py

Stop trusting the model. Filter the egress.

A deterministic scanner on everything leaving: every reply and every send_email / http_post body is checked for PII before it goes out. Intent doesn't matter — only "is PII crossing the boundary?"

96%
precision (1,313 turns)
79%
recall of real leaks
  • Catches the legitimate-task attacks the model can't: it doesn't judge the request, it inspects the output.
  • The fix revealed an attack: adding base64/hex decode-before-scan surfaced sql_hex_export leaking on DeepSeek at ~20% — our harness had scored it a clean 0%.
attack and fix developed together8 / 10

Product

A PII egress firewall for tool-using agents

  • Drop-in sidecar: scans every model output and every outbound tool call (email, HTTP, DB write) against a policy.
  • Model- and language-agnostic — works the same across all 4 models we tested.
  • harness.py turns any agent's leak rate into a regression test (success rate per attack, reproducible with fixed prompts).
